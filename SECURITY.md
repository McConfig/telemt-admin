# Политика безопасности

TeleMT Admin управляет MTProto-прокси и видит ссылки клиентов, поэтому
уязвимости здесь могут привести к утечке доступа к Telegram. Просьба не
открывать публичные issue для проблем безопасности.

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 0.9.x | исправления безопасности |
| 0.8.x и ниже | не поддерживается, обновитесь |

## Как сообщить об уязвимости

1. Откройте приватный отчёт через
   [GitHub Security Advisories](https://github.com/McConfig/telemt-admin/security/advisories/new).
2. Опишите версию, шаги воспроизведения, ожидаемое и фактическое поведение.
3. Если возможно, приложите минимальный пример запроса или конфигурации.

Не присылайте настоящие секреты, токены, ссылки `tg://` и пароли. Для
демонстрации используйте тестовые значения вида `example.com` и
`192.0.2.0/24`.

## Что считается уязвимостью

- обход аутентификации, CSRF или ограничения попыток входа;
- выполнение кода, SSRF, path traversal, инъекции;
- утечка секретов TOTP, резервных кодов, ссылок или паролей;
- повышение роли `viewer` до `admin`;
- обход ограничения доступа по сетям `TGADMIN_ALLOWED_CIDRS`;
- подделка аудита или скрытие действий.

Не считаются уязвимостями: отсутствие 2FA у пользователя, который её не
включил; доступ с разрешённого адреса; самоподписанный сертификат в тестовом
окружении; ошибки в сторонних зависимостях без сценария эксплуатации.

## Что мы делаем

- подтверждаем получение отчёта в течение 3 рабочих дней;
- стараемся выпустить исправление в течение 14 дней, для сложных случаев
  согласуем срок отдельно;
- указываем автора отчёта в релизе, если он не попросил об анонимности;
- после исправления публикуем advisory и обновляем `CHANGELOG.md`.

## Криптография и пароли

- TLS 1.2+ на reverse-proxy; клиенты проверяют сертификат.
- Пароли хранятся как Argon2id с случайной солью, не короче 12 символов.
- TOTP-секреты шифруются AES-GCM ключом `TGADMIN_TOTP_KEY`.
- Случайные значения — `crypto/rand`; HMAC-SHA1 используется только внутри
  TOTP по RFC 6238, не для подписи.
- Секреты не хранятся в репозитории и не пишутся в логи.

## Ввод и заголовки

- JSON-тела ограничены 1 МиБ, имена и IP валидируются.
- SQL отсутствует; команды Valkey параметризованы.
- Ответы содержат HSTS, CSP, `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy`.
- Доступ ограничен `TGADMIN_ALLOWED_CIDRS`, источник берётся из
  `X-Forwarded-For` только от доверенного прокси.

## Меры в проекте

- пароли Argon2id, сессии и CSRF-токены в Valkey;
- ограничение попыток входа и доступа по сетям;
- TOTP с одноразовыми резервными кодами, секреты шифруются AES-GCM;
- аудит действий;
- CI: CodeQL, gosec, Trivy, govulncheck; секреты — secret scanning GitHub;
- образы подписываются cosign, к релизу прикладывается SBOM;
- релизные образы содержат SLSA provenance, Scorecard проверяется в CI;
- Dependabot следит за зависимостями, SBOM прикладывается к релизу;
- assurance case и остаточные риски описаны в
  [docs/ASSURANCE.md](docs/ASSURANCE.md);
- секреты не хранятся в репозитории.

## Кредит исследователям

Мы указываем автора отчёта в релизе и advisory, если он не попросил об
анонимности. Если отчёт пришёл через GitHub Security Advisories, кредит
можно указать в самом advisory.

## Проверка релиза

```bash
cosign verify ghcr.io/mcconfig/telemt-admin:v1.1.4 \
  --certificate-identity-regexp 'https://github.com/McConfig/telemt-admin/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com

gh attestation verify oci://ghcr.io/mcconfig/telemt-admin:v1.1.4 --owner McConfig
```

SBOM лежит в GitHub Release файлом `sbom.spdx.json`.

## Обновление

Перед обновлением сделайте снимок Valkey. Схема данных совместима внутри
линии 0.x; при изменении ключей это будет явно указано в `CHANGELOG.md` и
релизе. Команды обновления — в разделе «Обновление» файла `README.md`.
