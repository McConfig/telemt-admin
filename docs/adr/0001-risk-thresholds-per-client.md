# ADR-0001: пороги риска на клиента

- Статус: принято
- Дата: 2026-11-25
- Контекст: версия 1.2.0

## Проблема

Риск клиента считается по трём глобальным значениям:

- `TGADMIN_RISK_IPS_WARN` — предупреждение по числу активных адресов;
- `TGADMIN_RISK_IPS_HIGH` — высокий риск по числу активных адресов;
- `TGADMIN_RISK_DISTINCT_7D` — предупреждение по числу адресов за 7 дней.

Одно значение не подходит разным устройствам. Роутер дома законно держит
несколько адресов и меняет их при переподключении провайдера, а телефон
должен вызывать вопросы уже на третьем адресе. Глобальные пороги
приходится завышать, и тогда реальные утечки ключей теряются в шуме.

## Решение

Хранить необязательные переопределения на клиента в Valkey по ключу
`risk:user:<name>`:

| Поле | Тип | Смысл |
|---|---|---|
| `warn_ips` | число | предупреждение, если активных адресов больше |
| `high_ips` | число | высокий риск, если активных адресов больше |
| `distinct_7d` | число | предупреждение по уникальным адресам за 7 дней |
| `new_countries` | `0`/`1` | считать ли новую страну риском |

Отсутствие ключа или поля означает наследование глобального значения.
Пустой объект в API удаляет ключ. `new_countries` по умолчанию `true`,
поэтому поведение существующих установок не меняется.

Проверки: `0 <= warn_ips < high_ips <= 1000` и
`0 <= distinct_7d <= 10000`. Ограничения не дают случайно отключить риск
нулевыми порогами и защищают от бессмысленных значений.

Расчёт риска использует переопределение в трёх местах: список клиентов,
сводка и сборщик метрик. Метрика `tgadmin_user_risk_level` тоже учитывает
индивидуальные пороги.

## Альтернативы

1. **Хранить пороги в telemt.** В Control API нет таких полей, а расширять
   чужой API ради UI-настройки нельзя.
2. **Глобальные профили («телефон», «роутер»).** Меньше гибкости и ещё одна
   сущность для управления. Отложено до появления реального спроса.
3. **Отключить риск для клиента целиком.** Скрывает проблему. Вместо этого
   можно поднять пороги и отключить реакцию на новые страны.
4. **Хранить в конфигурационном файле.** Настройка меняется из интерфейса,
   поэтому файл не подходит.

## Последствия

- Новый ключ Valkey не требует миграции; откат на старую версию безопасен:
  старый код просто не читает `risk:user:*`.
- Один дополнительный `HGETALL` на клиента при построении списка, сводки и
  среза сборщика. При десятках клиентов это незаметно; при сотнях нужно
  перейти на pipeline или MGET.
- В API появились `riskThresholds` и `riskDefaults`, в аудите — действие
  `user.risk`.
- Настройка доступна только роли `admin`.
- Пороги не влияют на лимиты telemt: это отдельный слой наблюдения.
