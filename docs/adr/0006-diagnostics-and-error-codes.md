# ADR-0006: диагностика и коды ошибок Control API

- Статус: принято
- Дата: 2026-11-26
- Контекст: версия 1.6.0

## Проблема

При сбое оператор видел общее «telemt не отвечает» без указания, что именно
проверить. Состояние сборщика, GeoIP, вебхуков, бэкапов и требований 2FA
было разбросано по страницам.

## Решение

1. Добавить `GET /api/diagnostics` только для admin. Ответ собирает
   доступность и задержку Control API, состояние сборщика, GeoIP, Valkey,
   вебхуков, бэкапов и 2FA, а также список предупреждений.
2. Ввести стабильные коды ошибок `telemt_*` в `internal/telemt`: transport,
   HTTP-статусы, коды конфигурации, неверный ответ.
3. Возвращать в ошибках `code`, `message`, `hint`; не включать токены и
   секреты.
4. Показывать коды и подсказки на странице «Диагностика» и в ответах API.
5. Не менять текст успешных операций; коды нужны для автоматизации и
   разбора сбоев.

## Альтернативы

1. **Только логи.** Неудобно без SSH и не объясняет причину.
2. **Один общий код `telemt`.** Не даёт автоматизации и точных подсказок.
3. **Прятать коды от клиента.** Ломает диагностику во внешних системах.
4. **Показывать URL и токены.** Небезопасно.

## Последствия

- Ошибки Control API стали длиннее на поля `code` и `hint`, обратная
  совместимость по HTTP-статусам сохранена.
- Страница не заменяет журналы telemt и systemd, но сокращает путь к ним.
- Секреты в диагностику не попадают.
- Проверки выполняются по запросу, без фонового мониторинга.
