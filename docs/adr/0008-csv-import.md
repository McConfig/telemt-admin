# ADR-0008: импорт клиентов из CSV

- Статус: принято
- Дата: 2026-11-26
- Контекст: версия 1.8.0

## Проблема

Клиентов приходилось создавать по одному через форму. При переносе списка
из таблицы или восстановлении после сбоя оператор вручную повторял имя,
секрет и лимиты для каждой строки, а ошибки замечал только после создания.

## Решение

1. Добавить `POST /api/users/import` с параметром `dryRun`:
   `dryRun=1` проверяет файл, `dryRun=0` создаёт клиентов. Без параметра
   выполняется проверка.
2. Принимать сам CSV в теле запроса (`text/csv`), до 1 МБ и 1000 строк.
3. Требовать заголовок. Обязательна только колонка `name`; остальные
   колонки необязательны. Поддерживать `,` и `;`, BOM, кавычки и пустые
   поля.
4. Считать неизвестные и повторяющиеся заголовки ошибкой файла, а не
   молча игнорировать: так опечатка в названии колонки не приведёт к
   потере лимитов.
5. Проверять поля теми же правилами, что и обычное создание: имя, секрет,
   числовые лимиты, период квоты, RFC3339 и `enabled`.
6. Существующего клиента помечать `skip` и не изменять. Повтор имени
   внутри файла считать ошибкой у второй строки.
7. Сначала проверять все строки, затем создавать валидные
   последовательно. Ошибка одной строки не останавливает импорт.
8. Писать аудит `user.create` на каждого созданного и сводное
   `user.import` на применение. Проверка без записи аудит не пишет.
9. В интерфейсе показывать предпросмотр до создания: номер строки, имя,
   статус и причину ошибки; применять только после отдельного нажатия.

## Альтернативы

1. **Разбор CSV в браузере.** Дублировал бы правила валидации и позволял
   обойти серверные ограничения.
2. **Обновлять существующих клиентов.** Опасное поведение по умолчанию:
   импорт мог бы перезаписать лимиты и секреты.
3. **Останавливаться на первой ошибке.** Оператору пришлось бы исправлять
   файл по одной строке.
4. **Транзакционный импорт.** Control API telemt не предоставляет общую
   транзакцию; откат уже созданных клиентов был бы опаснее частичного
   импорта с точным отчётом.
5. **Поддержка человеческих единиц (`10GB`).** Удобно, но добавляет
   неоднозначность и ошибки округления; выбран точный размер в байтах.

## Последствия

- Импорт не атомарен: при сбое часть клиентов может быть создана. Отчёт
  показывает, какие строки созданы, пропущены и завершились ошибкой.
- Секрет можно не указывать: telemt сгенерирует его сам.
- Существующие клиенты не обновляются; для изменения лимитов используется
  карточка клиента.
- Ограничение 1000 строк и 1 МБ защищает Control API и время ответа.
- Новых ключей Valkey и переменных окружения нет.
