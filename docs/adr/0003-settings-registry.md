# ADR-0003: реестр глобальных настроек

- Статус: принято
- Дата: 2026-11-25
- Контекст: версия 1.3.0

## Проблема

Глобальные параметры задаются только через env и применяются при
перезапуске: пороги риска, домашняя страна, интервал сбора, retention,
TTL сессий, режим ссылок. Шаблонов лимитов нет. Статус бэкапов и системные
сведения доступны только через SSH.

Нужна одна страница, где видно все настройки, включая ещё не реализованные,
и понятно, что можно менять, что требует перезапуска, что доступно только
для чтения и что появится позже. Ошибка в сетевой настройке не должна
заблокировать доступ.

## Решение

1. Реестр скалярных настроек в коде: ключ, раздел, тип, статус, версия
   появления, признак перезапуска, ограничения и значение по умолчанию из
   env.
2. Переопределения хранятся в `settings:global`, версия — в
   `settings:version`. Действующее значение: переопределение → env →
   встроенное.
3. `PUT /api/settings` проверяет версию, валидирует поля и меняет только
   `active`; `readonly` и `planned` отклоняются.
4. Каждое изменение пишется в аудит `settings.update` со старым и новым
   значением.
5. Шаблоны лимитов — отдельная сущность в `limit:templates` с шаблоном по
   умолчанию; они не часть реестра, потому что это наборы, а не скаляры.
6. Бэкапы и системная панель — отдельные эндпоинты. Приложение запускает
   `BGSAVE`, но не копирует и не ротирует снимки.
7. Сетевые параметры, Base URL, Cookie Secure, пути GeoIP и секреты
   показываются только для чтения.

## Альтернативы

1. **Только env и документация.** Не решает задачу и требует SSH.
2. **Универсальная форма без реестра.** Каталог пришлось бы дублировать на
   клиенте и сервере, а planned-пункты добавлять вручную.
3. **Разрешить менять всё, включая CIDR и Base URL.** Риск мгновенно
   потерять доступ без возможности вернуться через UI.
4. **Хранить настройки в файле.** Не подходит для изменения из интерфейса
   и нескольких процессов.

## Последствия

- Новые ключи не требуют миграции. Откат на 1.2.x безопасен: старый код их
  не читает.
- Интервал сбора и retention применяются после перезапуска; UI это
  показывает. Домашняя страна, риск, TTL новых сессий и режим ссылок
  применяются сразу.
- Домашняя страна меняет только новые наблюдения; старая история не
  переписывается.
- Переопределения читаются из Valkey с коротким кэшем; несколько
  экземпляров приложения не поддерживаются.
- Секреты не возвращаются API и не попадают в аудит.
- Шаблоны лимитов применяются к формам, но не сохраняются автоматически.
