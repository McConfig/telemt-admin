# ADR-0012: Обмен конфигурацией и редактор прокси

- Статус: принято
- Дата: 2026-11-27
- Контекст: версия 2.0.0

## Проблема

Настройки tgadmin жили только в Valkey и менялись через интерфейс. Перенести
их на другую установку, поделиться набором настроек или сохранить снимок
перед экспериментом было нельзя. Конфигурация telemt (`config.toml`) жила
отдельно и правилась вручную, поэтому источник правды был размазан между
файлом, скриптом и панелью.

## Решение

1. Экспорт и импорт — один YAML-бандл `tgadmin.telemt/v1` с блоками:
   системные настройки, шаблоны лимитов, прокси, пользователи UI,
   сервисные аккаунты, клиенты.
2. Секреты по умолчанию не выгружаются. Включение требует текущий пароль
   и TOTP-код, если он включён.
3. Импорт двухшаговый: precheck строит diff, конфликты и список удалений,
   apply применяет выбранные блоки.
4. Режимы: слияние и замена для настроек и прокси; для сущностей —
   создание, обновление по выбору и явное удаление отсутствующих.
5. Редактор прокси работает через Control API telemt: `GET /v1/config`,
   `GET /v1/config/schema`, `POST /v1/config/validate`, `PATCH /v1/config`
   с `If-Match` и `reload`, статус через `GET /v1/system/reload/{id}`.
6. tgadmin не монтирует `config.toml`, не пишет файл и не перезапускает
   контейнер.

## Альтернативы

1. **Монтировать `config.toml` и править файл.** Требует доступа к хосту,
   теряет комментарии, не даёт валидации и ревизий.
2. **Полный tar-архив каталога и Valkey.** Годится для бэкапа, но не для
   обмена настройками: нельзя выбрать блоки, показать diff и конфликты.
3. **Собирать YAML во фронтенде.** Дублирует валидацию, усложняет
   секреты и делает формат зависимым от браузера.
4. **Оставить только экспорт.** Не решает перенос настроек.

## Последствия

- Новые ключи Valkey `config:plan:<id>` с TTL 15 минут; миграции нет.
- Новые маршруты `/api/config/*` и `/api/proxy/*`, только для
  администратора с cookie-сессией.
- Формат `tgadmin.telemt/v1` становится публичным контрактом.
- TOTP-секреты и passkeys не переносятся: после импорта 2FA включается
  заново.
- Комментарии `config.toml` не гарантируются: источник правды — Control
  API.
- Откат на 1.x безопасен: новые ключи игнорируются, настройки и прокси
  остаются рабочими.
