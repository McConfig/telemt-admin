# Обновление TeleMT Admin

## Поддерживаемая схема

Версии `0.x` и `1.x` используют одни и те же ключи Valkey:

- `auth:*` — пользователи UI, сессии, ограничения входа, 2FA;
- `audit:events` — поток аудита;
- `iphist:*` — история адресов, страны, трафик;
- `iphist:dayfirst:*`, `iphist:daylast:*` — первое и последнее наблюдение
  адреса внутри дня (с 1.2.0, срок жизни 30 дней);
- `settings:global`, `settings:version` — глобальные настройки (с 1.3.0);
- `limit:templates`, `limit:template:default` — шаблоны лимитов (с 1.3.0);
- `trusted:*` — доверенные страны и адреса;
- `risk:user:*` — переопределения порогов риска (с 1.2.0);
- `iphist:geo:*` — последние агрегаты GeoIP.

При переходе между версиями внутри `0.x`/`1.x` миграции не требуются.
Ключи `risk:user:*` появились в 1.2.0: старая версия их не читает, поэтому
откат на 1.1.x безопасен и просто возвращает глобальные пороги.

Ключи `iphist:dayfirst:*` и `iphist:daylast:*` тоже появились в 1.2.0 и
имеют общий срок жизни 30 дней. Для дней, собранных до обновления, время
внутри дня отсутствует: отчёт покажет список адресов, первый и последний
раз за всё время, пик и новые страны, а колонки времени будут пустыми.
Откат на 1.1.x эти ключи игнорирует.

В 1.3.0 появились переменные `TGADMIN_HOME_COUNTRY` (по умолчанию `RU`) и
необязательная `TGADMIN_BACKUP_STATUS` с путём к JSON статуса бэкапов хоста.

В 1.4.0 добавлены переменные со значениями по умолчанию:
`TGADMIN_LOGIN_MAX_FAILURES=10`, `TGADMIN_LOGIN_WINDOW=15m`,
`TGADMIN_TOTP_PENDING_TTL=5m`, `TGADMIN_TOTP_MAX_ATTEMPTS=5`,
`TGADMIN_AUDIT_MAX_EVENTS=10000`, `TGADMIN_PASSWORD_MIN_LENGTH=12`,
`TGADMIN_DEFAULT_CHART_DAYS=30`, `TGADMIN_LOG_LEVEL=info`. Их можно
переопределить на странице «Настройки»; поведение по умолчанию не меняется.
Формат файла:

```json
{"lastRun":"2026-11-25T04:32:21Z","result":"ok","size":20480,"keepDays":14,"restoreTest":true}
```

Файл монтируется в контейнер только для чтения. Без него панель «Бэкапы»
показывает статус Valkey и кнопку `BGSAVE`, а статус хоста остаётся
недоступным.
Интервал сбора и retention, изменённые на странице «Настройки»,
применяются сразу: сборщик перечитывает интервал перед следующим циклом,
store обновляет окно хранения. Увеличение retention не возвращает данные,
которые уже истекли по старому TTL. Откат на 1.2.x безопасен: старый код
не читает `settings:*` и `limit:*`.
Если схема изменится, это будет явно указано в `CHANGELOG.md` и в описании
релиза.

## Перед обновлением

1. Сделайте снимок Valkey:

   ```bash
   ssh admin@192.0.2.10
   cd ~/lab/network
   sudo systemctl start valkey-backup.service
   ls -lh ~/backups/valkey/
   ```

   Ожидание: свежий `valkey-*.rdb.gz` в каталоге снимков.

2. Прочитайте `CHANGELOG.md` и описание релиза на GitHub.
3. Проверьте, что ключ `TGADMIN_TOTP_KEY` сохранён отдельно от сервера,
   если 2FA включена.

## Обновление

```bash
ssh admin@192.0.2.10
cd ~/lab/network
docker compose pull tgadmin
docker compose up -d tgadmin
```

Проверка:

```bash
ssh admin@192.0.2.10 \
  'curl -fsS http://127.0.0.1:8090/readyz'
```

Ожидание: `{"status":"ok"}`.

```bash
curl -fsS https://tgadmin.example.com/api/meta
```

Ожидание: версия из нового тега.

## Откат

1. Укажите в `docker-compose.yml` предыдущий тег:

   ```yaml
   image: ghcr.io/mcconfig/telemt-admin:v0.9.1
   ```

2. Поднимите контейнер:

   ```bash
   docker compose up -d tgadmin
   ```

3. Если новая версия повредила данные, остановите `tgadmin` и `valkey`,
   распакуйте последний снимок как `dump.rdb` в том `tgadmin_valkey` и
   запустите контейнеры. Порядок восстановления описан в разделе
   «Бэкап и восстановление Valkey» файла `README.md`.

Откат образа безопасен: схема Valkey совместима, старые версии просто
игнорируют новые поля.
