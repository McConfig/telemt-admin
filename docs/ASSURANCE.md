# Assurance case

Документ объясняет, почему проекту можно доверять в заявленных границах.
Это не гарантия отсутствия уязвимостей, а описание активов, угроз, мер и
способов проверки.

## Область

TeleMT Admin — локальный веб-интерфейс для управления клиентами MTProto-
прокси telemt. Он не является публичным сервисом, не хранит секреты
клиентов и не выполняет платежи.

## Активы

1. Ссылки `tg://proxy` и секреты клиентов.
2. Пароли и TOTP-секреты администраторов.
3. История IP и стран, по которой ищут утечки ключей.
4. Аудит действий.
5. Доступность прокси и интерфейса.

## Угрозы

| Угроза | Сценарий | Меры |
|---|---|---|
| Кража пароля | перебор, утечка из менеджера | Argon2id, лимит попыток, TOTP |
| Кража ключа | пересылка ссылки, чужое устройство | история IP, новые страны, алерты, перевыпуск |
| CSRF | сторонний сайт от имени админа | SameSite, CSRF-токен, проверка Origin |
| XSS | пользовательские заметки и имена | React escaping, CSP, запрет inline script |
| SSRF | healthcheck URL | адрес задаёт оператор, `#nosec` с обоснованием |
| Утечка секретов | коммит `.env` | secret scanning GitHub, push protection, `.gitignore`, CI |
| Подмена образа | компрометация реестра | cosign, SBOM, provenance |
| Утечка данных | доступ вне сети | allowlist CIDR, reverse-proxy, HTTPS |
| Отказ Valkey | потеря истории | ежедневный бэкап, restore-test |
| Компрометация зависимости | вредоносный пакет | lock-файлы, Dependabot, Trivy, CodeQL |

## Меры

- **Аутентификация:** Argon2id, сессии в Valkey, TOTP с резервными
  кодами, ограничение попыток, отключение пользователей.
- **Авторизация:** роли admin/viewer; viewer не видит ссылки и полные IP.
- **Ввод:** ограничение размера JSON, регулярные выражения для имён, IP
  через `netip`, запрет path traversal.
- **Криптография:** TLS 1.2+ на reverse-proxy, AES-GCM для TOTP-секретов,
  `crypto/rand`, HMAC-SHA1 только внутри TOTP по RFC 6238.
- **Заголовки:** HSTS, CSP, `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`.
- **Секреты:** только в окружении и менеджере паролей; в репозитории нет
  `.env`, ключей и реальных ссылок.
- **Сборка:** закреплённые digest базовых образов, минимальный distroless,
  nonroot, read-only корень, `cap_drop: ALL`.
- **Релизы:** CI-проверки, подпись cosign, SBOM, provenance, GitHub
  Release.

## Проверки

- Go-тесты, включая TOTP, CSRF, права, лимиты и ошибки.
- Vitest и Playwright для UI и сквозных сценариев.
- CodeQL, gosec, Trivy, govulncheck; секреты — secret scanning GitHub.
- Fuzz-тесты TOTP и разбора ссылок.
- Ручная проверка на стенде и на домашнем сервере.
- Восстановление Valkey из снимка.

## Остаточные риски

- Один сопровождающий: bus factor равен одному.
- Нет независимого внешнего аудита.
- TOTP уязвим к фишингу в реальном времени; WebAuthn пока не реализован.
- Frontend-покрытие 64%, не все ветки проверены.
- История IP зависит от GeoIP-баз и может ошибаться на границах сетей.
- Домашние клиенты за hairpin NAT могут выглядеть одним адресом, если
  split-horizon DNS не работает.

## Реагирование

Порядок сообщения об уязвимости, сроки и поддерживаемые версии — в
[SECURITY.md](../SECURITY.md). Инцидент с утечкой ключа: перевыпустить
секрет, завершить сессии, проверить историю IP и аудит, при необходимости
отозвать доступ к интерфейсу.
