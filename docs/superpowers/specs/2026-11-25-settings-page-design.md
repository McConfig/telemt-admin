# Страница «Настройки»: глобальные настройки TeleMT Admin

- Статус: принято
- Дата: 2026-11-25
- Целевая версия: 1.3.0
- Подход: гибрид C — реестр скалярных настроек плюс отдельные панели

## 1. Контекст

Сейчас глобальные параметры задаются только переменными окружения и
применяются при перезапуске. Пороги риска на клиента уже можно менять из
интерфейса, но глобальные значения, шаблоны лимитов, состояние бэкапов и
системная информация доступны только через `.env`, SSH и документацию.

Администратору нужна одна страница, где видно все настройки, понятно, что
меняется сразу, что после перезапуска, что доступно только для чтения, а
что появится в следующих релизах. Ошибка в сетевой настройке не должна
заблокировать доступ, поэтому опасные параметры остаются в env.

## 2. Цели

1. Показать полный каталог настроек, включая ещё не реализованные.
2. Дать менять безопасные глобальные параметры без SSH и перезапуска.
3. Хранить переопределения в Valkey, env оставить значением по умолчанию.
4. Вести аудит каждого изменения с прежним и новым значением.
5. Добавить шаблоны лимитов и применение их к клиентам.
6. Показать состояние Valkey, бэкапов, сборщика и GeoIP.
7. Не показывать и не редактировать секреты.
8. Не давать менять сетевые и инфраструктурные параметры из UI.

## 3. Не входит в задачу

- редактирование разрешённых CIDR, доверенных прокси, Base URL, Cookie
  Secure, путей GeoIP, адресов Valkey и telemt, токенов и ключей;
- управление расписанием и retention бэкапов из приложения;
- копирование и ротация снимков Valkey;
- доставка вебхуков и алертов;
- настройки на уровне отдельного пользователя UI, кроме уже существующих
  порогов риска на клиента;
- поддержка нескольких экземпляров приложения с общей записью настроек.

## 4. Каталог настроек

### 4.1. Риск

| Ключ | Тип | Статус | Применение | Ограничения |
|---|---|---|---|---|
| `risk.warn_ips` | int | active | сразу | 0–1000, меньше `risk.high_ips` |
| `risk.high_ips` | int | active | сразу | 1–1000, больше `risk.warn_ips` |
| `risk.distinct_7d` | int | active | сразу | 0–10000 |
| `risk.home_country` | string | active | сразу, к новым наблюдениям | ISO 3166-1 alpha-2 |
| `risk.new_countries` | bool | active | сразу | — |

`risk.new_countries` — глобальное значение по умолчанию. Переопределение на
клиента (`risk:user:*`) имеет приоритет.

### 4.2. Сбор и хранение

| Ключ | Тип | Статус | Применение | Ограничения |
|---|---|---|---|---|
| `collect.interval` | duration | active | сразу, следующий цикл | 10s–3600s |
| `retention` | duration | active | сразу, к новым записям | 168h–2160h |
| `session.ttl` | duration | active | к новым входам | 1h–720h |
| `links.mode` | enum | active | сразу | `tls`, `secure`, `classic` |
| `login.max_failures` | int | active | сразу | 1–1000 |
| `login.window` | duration | active | сразу | 1m–24h |
| `totp.pending_ttl` | duration | active | сразу | 1m–15m |
| `totp.max_attempts` | int | active | сразу | 1–20 |
| `audit.max_events` | int | active | сразу, к новым записям | 100–1000000 |
| `password.min_length` | int | active | сразу, к новым паролям | 8–128 |
| `ui.default_chart_days` | int | active | сразу | 7–90 |
| `log.level` | enum | active | сразу | `debug`, `info`, `warn`, `error` |

### 4.4. Только чтение

| Ключ | Источник | Почему нельзя менять |
|---|---|---|
| `network.allowed_cidrs` | env | риск блокировки доступа |
| `network.trusted_proxies` | env | риск подмены источника |
| `app.base_url` | env | cookie, CSRF, Origin |
| `app.cookie_secure` | env | безопасность cookie |
| `app.listen` | env | сетевой порт |
| `geoip.city_path` | env | нужен перезапуск |
| `geoip.asn_path` | env | нужен перезапуск |
| `valkey.url` | env | инфраструктура |
| `telemt.url` | env | инфраструктура |
| `valkey.password` | env | секрет |
| `telemt.token` | env | секрет |
| `totp.key` | env | секрет |
| `backup.status_path` | env | путь к статус-файлу хоста |

Секреты API не возвращает. Вместо значения — `secretSet: true|false`.

## 5. Приоритет значений

1. Сохранённое переопределение в `settings:global`.
2. Значение из env, прочитанное при старте.
3. Встроенное значение по умолчанию.

Ответ API для каждой настройки содержит `source`: `settings`, `env` или
`default`. Для `readonly` источник всегда `env`, для `planned` значения нет.

## 6. Хранилище

| Ключ | Тип | Назначение |
|---|---|---|
| `settings:global` | hash | переопределения активных настроек |
| `settings:version` | string (int) | версия для оптимистической блокировки |
| `limit:templates` | hash | имя шаблона → JSON |
| `limit:template:default` | string | имя шаблона по умолчанию |

Канонические значения: целые — десятичная строка, bool — `1`/`0`,
длительности — формат Go (`720h`, `60s`), enum — строка.

TTL у настроек нет. Удаление ключа возвращает значение из env.

## 7. Сервис настроек

Пакет `internal/settings`:

- упорядоченный каталог разделов и полей;
- вычисление действующих значений из env и Valkey;
- валидация одного поля и набора изменений;
- атомарное сохранение с проверкой версии;
- маскирование секретов;
- подписка на изменения для компонентов, которым нужно применять
  настройки на лету.

Чтение: один `HGETALL` на HTTP-запрос или тик сборщика. Для списка клиентов
настройки читаются один раз на запрос, а не на каждого клиента.

Сохранение: транзакция с проверкой `settings:version`. При несовпадении —
`409` и актуальные значения. При успехе версия увеличивается, кэш
сбрасывается.

## 8. Применение настроек

| Настройка | Как применяется |
|---|---|
| `risk.*` | читается в web и сборщике при каждом расчёте |
| `risk.home_country` | store получает домашнюю страну; сборщик и web считают иностранные адреса по ней |
| `risk.new_countries` | значение по умолчанию, per-client override сильнее |
| `session.ttl` | используется при создании новой сессии |
| `links.mode` | используется при формировании ответа клиента |
| `collect.interval` | сборщик перечитывает интервал перед каждым ожиданием |
| `retention` | `store.SetRetention` вызывается сразу при сохранении |
| `login.*` | `store.SetLoginPolicy` при сохранении |
| `totp.*` | читается в обработчиках входа |
| `audit.max_events` | `store.SetAuditMax`, применяется к новым записям |
| `password.min_length` | проверяется при создании и смене пароля |
| `ui.default_chart_days` | отдаётся в `/api/meta`, фронтенд использует для графиков |
| `log.level` | динамический `slog.LevelVar` |

Изменение домашней страны не переписывает уже сохранённую историю. В
интерфейсе есть пояснение: новые расчёты используют новую страну, старые
записи остаются как были.

## 9. API

### 9.1. Каталог и изменение

`GET /api/settings` — только admin.

```json
{
  "version": 4,
  "sections": [
    {
      "id": "risk",
      "title": "Риск",
      "description": "Пороги и домашняя страна",
      "settings": [
        {
          "key": "risk.warn_ips",
          "title": "Предупреждение, больше IP",
          "description": "Порог предупреждения по активным адресам",
          "type": "int",
          "status": "active",
          "value": 3,
          "default": 3,
          "source": "env",
          "restartRequired": false,
          "min": 0,
          "max": 1000
        }
      ]
    }
  ]
}
```

`PUT /api/settings`:

```json
{
  "version": 4,
  "values": {
    "risk.warn_ips": 4,
    "risk.high_ips": 8,
    "risk.home_country": "RU",
    "risk.new_countries": true,
    "session.ttl": "720h",
    "links.mode": "tls"
  },
  "reset": ["collect.interval"]
}
```

`reset` удаляет переопределение и возвращает значение из env. Ключ в
`reset` должен быть `active`; иначе `400`.

Правила:

- меняются только переданные ключи;
- неизвестный ключ, `readonly`, `planned` → `400`;
- ошибка валидации → `400` с `key` и `message`;
- конфликт версии → `409` с актуальным каталогом;
- успех → `200` с новым каталогом и версией.

### 9.2. Шаблоны лимитов

`GET /api/settings/templates`:

```json
{
  "default": "роутер",
  "templates": [
    {
      "name": "роутер",
      "maxIps": 5,
      "maxTcpConns": 20,
      "dataQuotaBytes": 0,
      "quotaPeriod": "month",
      "rateUpBps": 0,
      "rateDownBps": 0,
      "expirationDays": 0,
      "sourceDeny": [],
      "riskWarnIps": 4,
      "riskHighIps": 6,
      "riskDistinct7d": 20,
      "riskNewCountries": false
    }
  ]
}
```

`POST /api/settings/templates` — создать.
`PUT /api/settings/templates/{name}` — заменить.
`DELETE /api/settings/templates/{name}` — удалить.
`PUT /api/settings/templates/default` — `{"name":"роутер"}`.

Ограничения: имя `[A-Za-z0-9._-]{1,64}`, не больше 50 шаблонов, значения
лимитов как в `PATCH /api/users/{name}`. Ноль означает «без лимита».
Шаблон по умолчанию можно удалить только вместе с назначением другого.

Применение:

- страница создания клиента — выбрать шаблон, поля заполняются;
- страница лимитов клиента — кнопка «Заполнить из шаблона», без
  автоматического сохранения;
- «Создать шаблон из клиента» — диалог с текущими лимитами и порогами.

### 9.3. Бэкапы

`GET /api/settings/backups`:

```json
{
  "valkey": {
    "lastSave": "2026-11-25T04:32:21Z",
    "saveInProgress": false,
    "lastStatus": "ok",
    "keys": 1234,
    "memory": "2.1M"
  },
  "host": {
    "available": true,
    "lastRun": "2026-11-25T04:32:21Z",
    "result": "ok",
    "size": 20480,
    "keepDays": 14,
    "restoreTest": true
  }
}
```

`host` заполняется из необязательного файла `TGADMIN_BACKUP_STATUS`
(например, `/opt/backup-status/status.json`), смонтированного только для
чтения. Если файла нет, `available: false`, а UI показывает расписание и
ссылку на процедуру.

`POST /api/settings/backups/snapshot` — отправить `BGSAVE`, аудит
`settings.backup`, ответ `202`. Приложение не копирует и не ротирует
снимки.

### 9.4. Система и история

`GET /api/settings/system`:

```json
{
  "version": "v1.3.0",
  "commit": "abc1234",
  "uptime": "72h",
  "collector": {"up": true, "lastSuccess": "...", "lastError": ""},
  "geoip": {"loaded": true, "built": "2026-11-01T00:00:00Z"},
  "valkey": {"keys": 1234, "memory": "2.1M"},
  "counts": {"uiUsers": 3, "auditEvents": 500, "historyKeys": 900}
}
```

`GET /api/settings/history?limit=50` — события `settings.update` из аудита:
время, кто, ключ, `old -> new`, IP.

## 10. Интерфейс

Маршрут `/settings`, только admin. Пункт меню рядом с «Пользователи UI».

Разделы сгруппированы во вкладки: «Риск», «Сбор и данные», «Ссылки»,
«Шаблоны», «Безопасность», «Бэкапы», «Система», «Инфраструктура»,
«История». Вкладки с несохранёнными изменениями помечаются точкой.

Отрисовка полей:

- `active`: число, переключатель, select или ввод длительности;
- `readonly`: значение, замок, пояснение «изменяется через env»;
- `planned`: неактивное поле, метка версии и текст «появится в следующем
  релизе»;
- `secret`: «задан» или «не задан»;
- `restartRequired`: метка «после перезапуска».

Сохранение:

- общая кнопка «Сохранить» в разделе;
- индикатор несохранённых изменений;
- при `409` — предупреждение и кнопка «Загрузить актуальные»;
- при успехе — сообщение и обновление версии.

Мобильная вёрстка: поля в одну колонку, таблица шаблонов — карточки.

## 11. Валидация

Серверная, по метаданным реестра:

| Поле | Правило |
|---|---|
| `risk.warn_ips` | 0–1000 и меньше `risk.high_ips` |
| `risk.high_ips` | 1–1000 и больше `risk.warn_ips` |
| `risk.distinct_7d` | 0–10000 |
| `risk.home_country` | две латинские буквы, верхний регистр |
| `collect.interval` | 10s–3600s |
| `retention` | 168h–2160h |
| `session.ttl` | 1h–720h |
| `links.mode` | `tls`, `secure`, `classic` |
| шаблон | имя, лимиты, квоты и пороги как у клиента |

Пустые значения не сохраняются: для сброса к env используется массив
`reset` в теле `PUT`.

## 12. Аудит и конкурентность

- Одно событие на изменённый ключ: `settings.update`, target — ключ,
  result — `old -> new`.
- Одно событие на создание, изменение и удаление шаблона:
  `settings.template.create|update|delete`.
- Ручной снимок: `settings.backup`.
- Версия проверяется в транзакции; при конфликте изменения не применяются.
- Аудит пишется после успешной записи.

## 13. Безопасность

- Только роль `admin`, CSRF для `PUT`, `POST`, `DELETE`.
- Тело запроса не больше 1 МиБ.
- Allowlist ключей из реестра.
- Секреты не возвращаются, не логируются и не попадают в аудит.
- Сетевые и инфраструктурные настройки не редактируются.
- Значения проверяются на сервере, UI-валидация только подсказка.
- При ошибке сохранения настройки не применяются частично.

## 14. Ошибки

| Ситуация | Ответ |
|---|---|
| Нет прав | `403` |
| Неизвестный ключ | `400`, `key` |
| Неверный тип или диапазон | `400`, `key`, `message` |
| `readonly` или `planned` | `400`, `key`, причина |
| Конфликт версии | `409`, актуальный каталог |
| Ошибка Valkey | `500`, без секретов |
| Ошибка `BGSAVE` | `502` или `500` с текстом статуса |

## 15. Тесты

- Реестр: порядок, уникальность ключей, маскирование секретов.
- Валидация: все границы и взаимные ограничения.
- Приоритет: env, сохранённое значение, сброс к env.
- Конкурентность: две записи с одной версией, вторая получает `409`.
- Запрет `readonly` и `planned`.
- Шаблоны: CRUD, лимит 50, имя, шаблон по умолчанию, применение.
- Бэкапы: парсер статуса Valkey, отсутствие файла статуса хоста, `BGSAVE`.
- Web: права, CSRF, аудит, отсутствие секретов в JSON.
- Frontend: active, readonly, planned, secret, конфликт версии, шаблоны.
- E2E: открыть настройки, изменить порог, увидеть `planned`, создать
  шаблон, применить к клиенту, сделать снимок.

## 16. Внедрение и совместимость

- Миграции нет: новые ключи, env остаётся умолчанием.
- Откат на 1.2.x безопасен: старый код не читает `settings:*`,
  `limit:*`.
- Интервал и retention применяются без перезапуска.
- Домашняя страна влияет только на новые расчёты.
- После релиза обновить README, README.en, API, UPGRADE, CHANGELOG,
  ARCHITECTURE, ADR-0003 и скриншоты демо.

## 18. Критерии приёмки

1. Страница показывает весь каталог, включая неактивные пункты с версией.
2. Активные настройки сохраняются, применяются по таблице и попадают в
   аудит.
3. `readonly` и секреты нельзя изменить через API.
4. Конфликт версии не теряет чужие изменения.
5. Шаблоны создаются, редактируются, применяются к новому и существующему
   клиенту.
6. Кнопка снимка запускает `BGSAVE`, статус Valkey отображается.
7. Системная панель и история работают без секретов.
8. Тесты и e2e зелёные, покрытие не ниже текущих порогов.
9. Документация и ADR обновлены.
