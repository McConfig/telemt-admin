# WebAuthn/passkeys: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development или superpowers:executing-plans.

**Goal:** добавить passkeys как второй фактор после пароля, с регистрацией
в «Аккаунте», входом, удалением и аудитом.

**Architecture:** `go-webauthn/webauthn` проверяет протокол; credential
records и challenge хранятся в Valkey. Существующая pending MFA сессия
используется и для TOTP, и для passkey. Frontend использует
`@simplewebauthn/browser`.

**Tech Stack:** Go 1.26, chi, go-redis, `go-webauthn/webauthn` v0.18.2,
React 19, `@simplewebauthn/browser` 14.x, Vitest, Playwright CDP.

**Spec:** `docs/superpowers/specs/2026-11-27-webauthn-design.md`

## Global Constraints

- Passkey — только второй фактор после пароля.
- Только cookie-сессия; сервисные токены получают `403 session_required`.
- RP ID/origin строго из `TGADMIN_BASE_URL`.
- Challenge одноразовый, TTL 5 минут.
- В Valkey только публичные credential records.
- Аудит без credential и публичного ключа.
- Существующие TOTP и резервные коды не ломаются.
- Пороги: API 85%, UI 85/85/85/70, общий Go 80%.
- `- name:` в Ansible, если появятся, только на русском.

## Review Focus

1. Passkey нельзя зарегистрировать или удалить без текущего пароля.
2. Вход по passkey не обходит allowlist CIDR и не работает без pending MFA.
3. Challenge одноразовый, привязан к пользователю и сессии, истекает.
4. Нельзя удалить последний второй фактор при включённой обязательной 2FA.
5. Сброс 2FA администратором удаляет и TOTP, и passkeys; TOTP-вход продолжает работать.

- [ ] **Step 3: реализовать сервис**

- `webauthn.New(&webauthn.Config{RPID: cfg.BaseURL.Hostname(), RPDisplayName: "TeleMT Admin", RPOrigins: []string{cfg.BaseURL.Scheme + "://" + cfg.BaseURL.Host}})`.
- `User` реализует `webauthn.User`: handle SHA-256(username)[:16], name, displayName, credentials.
- Challenge хранится в `auth:webauthn_register:<session>` / `auth:webauthn_login:<pending>` с TTL 5 минут.
- `Finish` загружает и удаляет challenge, проверяет через verifier, сохраняет passkey.
- `webauthn_unavailable`, если BaseURL не HTTPS и host не localhost.

- [ ] **Step 4: API регистрации**

`GET /api/account/webauthn` — список без credential.
`POST .../register/begin` — `{"password":"...","name":"MacBook"}`,
проверяет пароль и лимит, возвращает options.
`POST .../register/finish` — тело credential, сохраняет, аудит
`passkey.create`.
`DELETE .../{id}` — `{"password":"..."}`, проверяет пароль и правило
последнего фактора, аудит `passkey.delete`.

Все маршруты требуют `requireSessionAdmin`? Нет: любой пользователь UI
управляет своими passkeys. Требуется cookie-сессия, не сервисный токен.

- begin возвращает options.
- finish с fake verifier создаёт сессию.
- без pending cookie → `401`.
- просроченный challenge → `401 webauthn_challenge`.

- [ ] **Step 2: реализовать**

`apiLogin`: если `u.TOTPEnabled || CountPasskeys>0`, создать pending MFA
сессию. `mfaRequired=true`; `totpRequired=true` оставить только при
`u.TOTPEnabled`.

`begin`: pending cookie → `GetPendingTOTP`, проверить allowlist,
`BeginLogin`, сохранить challenge под sessionID pending.

`finish`: проверить assertion, обновить sign count/last_used, удалить
pending, создать сессию, аудит `login.webauthn`, вернуть `meForUser`.
